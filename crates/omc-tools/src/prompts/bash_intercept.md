Use the dedicated tools rather than the shell for files: `read` to show a file or some of its lines, `grep` to search contents, `glob` to find files by name, `edit` to change a file and `write` to create or replace one. A command that does nothing but what one of them does exactly is not run, and the result names the call to make instead: `cat`, `less` or `more` of a few text files (`read` with the path and `:1-`), `head -n N` or `tail -n N` of one text file (`read` with a line range), and `echo`, `printf` or `cat <<'EOF'` writing text the shell does not expand over a file (`write`). Everything else runs as usual, at most with a one-line tip: searches with `grep` or `rg`, `find`, `ls -R`, `sed -i`, appending with `>>`, other options, pipelines, lists and commands sent to the background. When the user asks for a particular shell command, run that command as asked rather than swapping in a tool; if it is refused, say so and use the call the result names.
